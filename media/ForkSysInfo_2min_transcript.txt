ForkSysInfo: English Demonstration
English narration transcript
Narrated walkthrough of the report figures and recorded Linux command-line evidence.
Sources: media/cli/, media/diagrams/, evidence-cli/.

00:00  Build and project overview
ForkSysInfo is a C client and server built with a Makefile.
This English walkthrough uses the same console evidence and diagrams as the report.

00:10  One child process per connection
The parent accepts each TCP connection and forks one child process.
Each child serves its client while the parent keeps accepting connections.
Both programs dynamically link the shared utility library.

00:25  Length-prefixed TCP protocol
Each frame starts with a four-byte, big-endian payload length.
Lengths must be between one and four thousand ninety-six bytes.
Read loops handle partial TCP reads before processing.

00:39  System information and client commands
The SYSINFO request returns the host name, kernel, architecture, memory, and uptime.
PING and ECHO are also shown here, with replies from separate worker processes.

00:51  Concurrency: twelve clients and twelve children
Twelve C clients request a three-second sleep at the same time.
The process snapshot shows twelve children sharing parent process 2152.
All clients finish in 3.175 seconds, demonstrating concurrent service.

01:08  Robustness: fragmented input, idle clients, zombies
Three comparisons use the same abnormal inputs with robustness enabled and disabled.
Fragmented requests succeed with read loops. The idle timeout releases a stalled worker.
Reaping removes completed children. The unsafe version leaves a blocked worker and a zombie.

01:27  Two debug controls and shared-library linkage
Debug messages appear only when compile-time debug and the runtime flag are both enabled.
The linkage commands show both programs loading the same local shared library.

01:39  TShark analysis of the tcpdump capture
TShark shows the loopback handshake, data exchange, and orderly close.

01:45  Packet bytes: four-byte length followed by PING
The PING frame has a four-byte length header and a four-byte command.

01:51  Complete integration results
The complete integration run passes all eleven test groups.
Source and reproduction commands are included.
